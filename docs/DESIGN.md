# CodexQuotaBar 视觉设计规范

> 状态：设计基线（持续维护）
>
> 适用范围：macOS 状态栏、下拉菜单、悬浮额度组件
>
> 原则：先更新设计文件并完成视觉确认，再修改实现代码。

## 1. 产品视觉目标

CodexQuotaBar 应保持轻量、紧凑、清晰，并尽量使用 macOS 原生视觉语言。

- 第一眼只回答“额度还剩多少”。
- 不用装饰性信息填充空间。
- 常驻组件不得遮挡工作内容，也不得依赖悬停才能读取核心额度。
- 使用系统字体、等宽数字和稳定尺寸，额度刷新时不得跳动或溢出。
- 颜色用于表达额度状态，不为 5h、7d 随意建立另一套装饰色。

## 2. 设计基线

### 2.1 字体

- 界面字体：macOS 系统字体（Swift 中使用 `NSFont.systemFont`）。
- 百分比数字：`NSFont.monospacedDigitSystemFont`。
- 字重只使用 Regular、Medium 或 Semibold。
- `0%`、`9%`、`59%`、`100%`、`--%` 必须使用同一布局宽度完成验证。

### 2.2 状态颜色

颜色只表示剩余额度状态：

| 状态 | 条件 | 标准颜色 |
|---|---:|---|
| 充足 | `> 60%` | `#47C77A` |
| 注意 | `20%–60%` | `#FFB347` |
| 紧张 | `< 20%` | `#FF5C66` |
| 暂无数据 | 无有效额度 | `#8CB0C9`，建议 65% 不透明度 |

同一额度的进度线和对应状态标记必须使用同一颜色。不能仅依赖颜色区分 5h 与 7d，必须同时保留文字或空间层级。

### 2.3 深色悬浮表面

- 背景：黑色，约 58% 不透明度。
- 未使用额度轨道：白色，约 16% 不透明度。
- 主文字：白色。
- 次要文字：白色，约 70%–82% 不透明度。
- 圆角采用连续胶囊轮廓，圆角半径等于组件高度的一半。
- 阴影保持克制，只用于从桌面背景中分离组件。

## 3. 已确认组件

### 3.1 状态栏

- 同时展示 5h 和 7d。
- 每个周期使用 5 个等高额度条，每条约代表 20%。
- 顺序固定：5h 在上，7d 在下。
- 额度条靠近百分比，右侧不增加 Codex 图标。
- 延续 `docs/assets/status-bar-preview.png` 的紧凑布局。

### 3.2 传统圆形悬浮球

- 外环表示 5h，视觉优先级更高。
- 内环表示 7d。
- 外环线宽大于内环；现有比例基准约为 `4.5 : 3.2`。
- 轨道从顶部开始，按顺时针方向表示剩余额度。
- 状态参考：
  - `docs/assets/floating-ball-preview.png`
  - `docs/assets/floating-ball-warning-preview.png`

## 4. 双额度胶囊确认方案

> 状态：已于 2026-09-04 完成方向确认，可作为下一步实现基线。实现必须通过第 7 节的布局边界验收。

可编辑设计源：`docs/design/floating-capsule-v0.4.2.drawio`

### 4.1 结构

- 建议目标尺寸：约 `128 × 50 px`；最终尺寸以真实 macOS 截图验收为准。
- 额度轨道沿整个胶囊轮廓绘制：
  - 外轨：5h，较粗，视觉优先。
  - 内轨：7d，略细。
- 中间内容左右分区：左侧 5h，右侧 7d。
- 中央可使用一条低对比度分隔线，但不得抢占视觉注意力。
- 两侧均显示周期和剩余百分比，不显示 Token、重置时间或其他信息。

### 4.2 颜色与线宽

- 两条进度轨均严格使用第 2.2 节的状态色。
- 不为外轨、内轨设置固定蓝色或青色身份色。
- 外轨和内轨通过位置、线宽以及内部标签区分。
- 线宽应明显高于上一版示意稿，并延续传统圆环约 `4.5 : 3.2` 的层级比例。
- 未完成部分统一使用第 2.3 节的白色半透明轨道。

### 4.3 内容层级

- 5h 位于左侧，数字字号和字重可以略高于 7d。
- 7d 位于右侧，保持清晰但降低一级视觉权重。
- 百分号可以比数字小，但必须保持基线稳定。
- 数据缺失显示 `--%`，不得改变组件大小。

## 5. 交互规范

- 整个悬浮组件均可拖动。
- 位置记忆必须按组件完整尺寸进行屏幕边缘约束。
- 核心额度始终可见，不依赖悬停。
- 悬停详情只显示 5h、7d 百分比及重置时间。
- 点击可固定详情；点击组件外部收起详情。
- 多显示器切换、分辨率变化和全屏空间中不得越界。

## 6. 动效规范

- 额度刷新只更新进度和数字，不改变外框尺寸。
- 数字变化不得产生横向跳动。
- 不使用循环动画、闪烁或持续发光。
- 如对额度线做过渡，进度应沿同一轨道平滑变化，并遵守“减少动态效果”系统设置。

## 7. 设计验收清单

设计稿确认前：

- [ ] 提供放大预览和 1:1 实际尺寸预览。
- [ ] 使用本文件规定的状态色、背景和字体方向。
- [ ] 验证 5h、7d 的层级和含义无需猜测。
- [ ] 用户明确确认设计稿。

实现完成后：

- [ ] 验证 `0%`、`9%`、`59%`、`100%`、无数据状态。
- [ ] 验证文字不溢出、不裁切、不抖动。
- [ ] 验证左右边缘、多显示器和全屏空间。
- [ ] 验证拖动、位置保存、悬停及点击外部收起。
- [ ] 运行自动化测试、构建和签名校验。
- [ ] 重启实际应用并截图，与已确认设计稿逐项对照。

## 8. 变更流程

每次视觉改动按以下顺序执行：

1. 更新本设计文件，标明“候选”或“已确认”。
2. 生成接近真实尺寸的效果图。
3. 用户确认效果图。
4. 修改 Swift/AppKit 实现。
5. 完成测试、构建、签名和实机截图验收。
6. 更新 README 预览、CHANGELOG 和版本说明。
7. 获得发布授权后再提交、推送或创建 Release。
